## What was built

**The derivation** (`frontend/src/pages/claimDerivation.ts`, new, pure). The page has three sources: the claim record, the run summaries, and the latest run's audit rows, which the page now fetches once (`useAuditEntries(correlationId, enabled)`; nothing for a claim never run) and passes to everything that reads them (plan D2): the status line, the runs list, the review panel and the Decision card. A summary holds no settlement figure, no failing agent and no human decision, so everything the page says beyond the stored status comes from the rows: `latestRun` (the first summary, as the API orders them and as `api/human.py` chooses the run a decision lands on), `deriveRunOutcome` (the settled figure from the `pipeline_settled` row, the failing agent from the `pipeline_aborted` row, and — since the additions — a person's decision from the human row), `deriveStoppedAt` (a mid-pipeline claim status meeting an abort row), `deriveDecision` (the last `human` row's `decision`, `decided_by`, `comment`, `decided_at`; a blank comment is none) and `deriveWhyHere` (the fired rules, or the one synthetic fail-closed rule when the Guardrail itself threw). It reuses `deriveAbort`, `deriveFiredRules`, `deriveCards` and `agentLabel` from `runDerivation.ts`.

**The claim card** (`pages/ClaimDetailPage.tsx`, rewritten). Ten labelled fields in words, labelled as the form labels them: claim number and policy number in monospace (the only two), then the type through `claimTypeLabel`, the amount through `formatUsd`, the jurisdiction, the loss and reported dates through the new `formatDate` (a calendar date formatted in UTC, so "2026-02-10" is 10 February in New York as in London), *Submitted* through `formatDateTime`, the status badge through `claimStatusLabel`, the description under its label. Beside the badge, one line when the badge alone would mislead: "The latest run stopped at the Adjuster." with *latest run* linked, when a part-way status meets an abort row; "A run is in progress." linked, while the latest run has no outcome. *← Claims list* above the card.

**The runs** (`RunsList`, `RunLine`, `CompareControls`). One line per run, newest first: a tick box named "Select the run of 10 Nov 2026, 17:24", the start time as the link, a *latest* badge on the first, the kind of run (`variantLabel`), the outcome — "Settled at $82,500" or "Aborted at the Adjuster" on the latest line from its rows, the outcome word through `runStatusLabel` on the others (plan D1: no request per run) — the short id, and an *Audit log* link. With two or more runs the hint "Tick two runs to compare them side by side." and *Compare selected* are always present, the button disabled until exactly two are ticked with `tooltips.disabledCompareNeedsTwo` leading `tooltips.compareSelected`; a third tick drops the earliest. A claim never run reads "No runs yet. Go back to the Claims list and press Process on this claim." with the link.

**The human review panel** (`components/HumanReviewPanel.tsx`, rewritten). Takes `{claimId, correlationId, rows, loading}` from the page instead of fetching, and reads in the order a reviewer needs: *Why this claim is here* (the fired rules through `ruleLine`; the fail-closed case through the synthetic rule, `FAIL_CLOSED_DESCRIPTION` now exported from `copy/run.ts`), *Recommended settlement* (the run page's Adjuster sentence, "Recommends $820,000 (85% confident)", from `deriveCards`), *The Adjuster's reasoning*, *Guardrail* (the card's sentence with the flag's detail beneath: "Failed: cited policy wording the policy does not contain" and the Coastal Surge Rider for Coral Bay), *Retrieved policy passages* (unchanged from Prompt 27). Labelled *Your name* and *Comment (optional)*; the buttons disabled until a name is typed, with "Enter your name to decide." while they are (D5); under them, checked against `api/human.py`, "Approve marks the claim Settled; the Adjuster's recommendation above stands as the settlement.", "Reject marks the claim Rejected; no settlement is made.", "Your name, your comment and the time are written to the audit trail under this run." After a decision the panel invalidates `['claim', id]` **and** `['audit', correlationId]`, so the Decision card appears without a reload.

**The Decision card** (`components/DecisionCard.tsx`, new). In the panel's place once the latest run's rows hold a human row: "Rejected by Dermot on 10 Nov 2026, 18:50.", the comment quoted or "No comment was left.", and "The decision is recorded in the audit trail under the run it was made on." with *the run* linked. Its first two lines are `DecisionSummary`, shared with the run page since the additions.

**The words.** Every sentence lives in new `copy/claim.ts` (`claimCopy`); a sentence with an in-app link is a `Segment[]` rendered by new `components/Sentence.tsx`. `copy/labels.ts` split `statusLabel` into `claimStatusLabel` and `runStatusLabel` (D4 as changed): a claim stored `aborted` reads *Rejected* on the Claims list and the claim page, a run's `aborted` reads *Aborted* on the run page and in the runs list; the stored value and the badge colour are unchanged. `copy/tooltips.ts` gained `compareSelected` and `disabledCompareNeedsTwo`; `copy/format.ts` gained `formatDate`; `api/types.ts` `ClaimStatus` gained `aborted` (D6, type only). The Guide's `tryMore[0]`, `tryMore[1]` and *Reading a run page* were reworded; `docs/walkthrough.md`'s *Human review* *Screen* line names the Decision card (O1). D7: the addendum's date for run `0eb6b1cc` was corrected from 12 to 11 November in the Prompt 29 report, the build log and `CLAUDE.md`.

The run page's header derivations moved into one `headerFacts` helper so the page component stays at 50 lines.

## Findings and deviations from the plan

- **Step 4 of the verification approved an existing claim.** The plan and the prompt's constraints asked for a claim created in the session, so that no run the record cites would change. Dermot approved the Northwood claim of the Phase 10 verification instead. The run and its rows are unchanged; the approval row was appended under the same run; the claim now reads *Settled* and, since the additions, its run reads *Approved*. Recorded in register R-25 and noted beside each description of run `67bdf225` in `CLAUDE.md`.
- **D4 changed at the gate** (register R-24): the plan recommended keeping *Aborted* on a rejected claim's badge; Dermot ruled *Rejected* for a claim, *Aborted* for a run, and the label split followed.
- **The run line read "Awaiting human review" on a decided claim** at the first verification, because the summary's status does not change on a human decision; the plan had noted it. The second addition closes it by reading the human row; Prompt 31's additive `human_decision` field on the summary would let pages without the rows (the compare page, the MCP run summaries) say the same.
- **Chrome returned no screenshots** in this session (the renderer timed out on every `screenshot`); clicks by element reference did not register either, so the compare flow was driven through the page's own JavaScript and the evidence throughout is the rendered text.
- **Function size.** `DecisionForm` is 46 lines, a flat block of two fields and two buttons; `LabelledField` was extracted to bring it under the limit. `RunDetailPage` was 51 lines before this prompt and 50 after the `headerFacts` helper; `ClaimsPage` is 75 (Phase 6's component, a flat JSX tree, untouched beyond the one cell) and carries no exception comment — a tidy-up for the Claims page's next iteration.
- **`uv.lock` carried the old project version.** The `pyproject.toml` bump in `9915ac7` did not update the lockfile's own `agentic-claims-poc` version; the regeneration script's `uv run` synced it at close-out and it is committed with the close-out.
- **The Azure database holds 31 claims** at the close (29 when the plan surveyed it on 13 November); the two new ones were created in Dermot's reading of the pages. The approval row brings the audit trail to row 185.
- **`ClaimStatus` lacked `aborted`** in the frontend's type for the API's response; corrected as a type (D6), no runtime change.
- Prettier was run on the touched files only; the nine untouched files that fail `prettier --check` on `main` are unchanged.
